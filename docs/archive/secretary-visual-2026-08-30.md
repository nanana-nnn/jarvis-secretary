## 2. 構図が変わって成立しなくなること

### 2.1 「淡い面のなかに紫の一点」という構造が消えた

8/28 ペアは、淡い肌の面に紫の光が一点あるだけだった。
だから画面側を無彩色寄りに保ち、**紫を一点に保つ**設計（`--accent` を氷色にし、
`--glow` を瞳にだけ使う）が成立した。

新素材は**全面にプリズム状の高彩度が散っている**。主要色は青紫 `#646899`、白 `#E5E6F0`、
空色 `#6B99CF`、藍 `#4159B6`、加えて黄・橙・マゼンタが点在する。
一点に絞る対象が存在しないので、同じ手は使えない。

そのまま今の配色を当てると、次のどちらかになる:

- UI の氷色の線が絵の彩度に負けて見えなくなる
- 線を強めると、絵と競って画面が騒がしくなり、状態が読めなくなる

### 2.2 THINKING の「紫の脈」が意味を失う

8/29 に §15 を「THINKING は色ではなく脈で示す」と改訂したが、
その前提は「awake の紫が一定である」ことだった。
新 awake の虹彩は**青から黄への多色バースト**で、紫は主役ではない。
脈で示す方針自体は残るが、**何を脈打たせるかを選び直す必要がある**（→ 5節）。

### 2.3 STANDBY の輝度が足りない

現行は `brightness(.30)`。これは L=61% の 8/28 素材向けに決めた値。

初代素材で設計意図どおりだった実効輝度は **23% × 0.42 ≒ 9.7%**。
新素材で同じ実効輝度にするには `0.097 / 0.57 ≒ **0.17**`。

**`brightness(.17)` 前後まで落とす。** あわせて `saturate(.2)` を掛け、
S 平均 41% を初代の 8% 帯へ寄せる。`DESIGN.md` §16（OLED 常設）への適合はこの2つで担保する。

### 2.4 顔の向きが変わり、視線の対角が計器から外を向く

新素材は眼鏡の枠と髪の流れが **左下→右上**の対角を作る。
顔を右ペインに置くと、この対角が画面外（右上）へ抜け、視線が計器（左）へ戻ってこない。

## 3. 新方針

> **色は全部、絵に持たせる。UI は色を持たない。**

8/28 版の「UI を無彩色寄りにして紫を一点に保つ」を一段進め、**UI から彩度を完全に外す**。
文字と線は白（`#FFFFFF`）の不透明度違いだけで組む。
唯一の例外を2つだけ置く（→ 6.1、および警告色）。

引き継ぐ原則（`design.md` / `DESIGN.md` から）:

- アクセントは面で塗らず、線と点で効かせる
- gradient text を使わない
- 明るい面を大きく置かない

新しく足す原則:

- **UI に色相を持たせない。** 絵と色で競らない
- **絵の上に文字を置かない。** 必ず溶けきった側に置く（→ 4.2）

### 3.1 トークン案

```
--fg          rgba(255,255,255,.94)   見出し
--fg-dim      rgba(255,255,255,.62)   本文
--fg-faint    rgba(255,255,255,.36)   ラベル
--rule        rgba(255,255,255,.14)   罫線
--bg          #05060a                 冷たい黒（絵の青紫側に合わせる）
--tint        （6.1 参照。既定は --fg と同じ白）
--warn        #ff5f6b                 警告専用
```

## 4. レイアウト

### 4.1 顔の位置

**顔は右ペインのまま据え置く**（`DESIGN.md` §15）。スタンドの向きと操作の記憶が変わるほうが損。

2.4 の対角の問題は、レイアウト反転ではなく**左側のフェザーを強める**ことで閉じる。
現行より暗く・広くして、絵の左端を計器側で確実に殺す。

`object-position` は **`38% 44%` を初期値**とし、実機で微調整する。

> 反転案（顔を左・計器を右）と鏡像反転案も検討したが、どちらも採らない。
> 前者はスタンド運用と §15 を壊す。後者は眼鏡のつるの刻印が裏返る。

### 4.2 文字の可読性

新素材は L 平均 57% と明るく、文字と重なると必ず読めなくなる。
**計器ペインの領域には絵の実効輝度を出さない**こと。フェザーで殺しきる。

## 5. 状態表現

顔の位置と画角は状態で動かさない（§15）。動かすのは目・輝度・線の3つだけ。

| 状態 | 絵 | 計器 |
|---|---|---|
| `BOOTING` | `brightness(.17) saturate(0)` | ビーコン消灯 |
| `SLEEP` | `brightness(.17) saturate(.2)` + 微小ドリフト | tick 18% |
| `WAKING` → `LISTENING` | `brightness(1)` へ 220ms | tick 62%、ビーコン 1s 周期 |
| `TRANSCRIBING` | 同上 | — |
| `THINKING` | **虹彩の彩度のみ 1.6s 周期で脈**（下記）| tick 46% |
| `APPROVAL` | 同上・脈なし | tick 100%、線を伸ばしきる |
| `SPEAKING` | 同上 | — |
| `ERROR` / `OFFLINE` | `brightness(.17) saturate(0)` | tick を無彩色に |

### THINKING の見せ方（2.2 の宿題）

新 awake の虹彩は多色バーストなので、色を足すと濁る。
**足すのではなく、虹彩の彩度を上下させる。**

```
虹彩の位置に円形マスクを置き、saturate(1.0) ↔ saturate(1.45) を 1.6s で往復
```

「考えている間、瞳の色が深くなる」。色相を追加しないので絵と競らない。
実装は虹彩位置（画像内 35% / 40%）に固定した円形の `backdrop-filter` を想定する。

## 6. Linux との連動

「PC 側の環境と繋げた演出ができるか」への回答。**採用2件・条件付き1件・不採用2件。**

### 6.1 採用 ── 差し色を caelestia の配色に追従させる（壁紙連動）

**演出の意味**: 眼鏡と瞳はプリズムである。PC の光を受けて散らす。
**壁紙を変えると、秘書の差し色が変わる。**

3節で UI から色を外したので、**画面のなかで唯一色を持つ点**を作れる。
そこに caelestia のスキームの `primary` を入れる。散らしているのは絵、
一点だけ色を受け取るのが UI、という構造になる。

**入れる場所は2箇所だけ**（増やすと 3節の方針が崩れる）:

- ビーコン（5px の点）
- tick の先頭 22%

**根拠となる既存資産**:

- `~/.local/state/caelestia/scheme.json` が壁紙変更のたびに再生成される（`colours.primary` ほか）
- `~/.config/caelestia/cli.json` の `theme.postHook` で任意コマンドを走らせられる。
  すでに Obsidian 向け CSS のコピーで実績がある

**実装方針**（2案。前者を推す）:

1. `server` が `scheme.json` を watch し、変化したら `/ws` へ push
   ```json
   { "type": "scheme.changed", "primary": "#1b696f", "ts": 0 }
   ```
   iPhone 側は CSS 変数 `--tint` を差し替えるだけ。再読み込み不要
2. `theme.postHook` から `server` の HTTP エンドポイントを叩く（watch 不要・PC 側の設定が増える）

**フォールバック**: `scheme.json` が読めないときは `--tint` を白のままにする。色が消えるだけで壊れない。

### 6.2 採用 ── 配色の出所を1つにする（quickshell パネルとの乖離解消）

`~/.config/quickshell/jarvis-shell/shell.qml:34` に、こう書かれている:

```
// 骨色とクリムゾン。iPhone UI（apps/iphone-ui/src/style.css）と同じ値
```

つまり PC の JARVIS パネルと iPhone UI は**同じ配色を共有する前提**で、
値が両方にハードコードされている。**そして 2026-08-29 の改修で既に乖離した**
（style.css は冷色へ、パネルはクリムゾンのまま）。

6.1 を入れるなら、パネルも同じ `scheme.json` を読ませる。
**両方が同じ出所を見る形にすれば、構造的に二度と乖離しない。**
これは演出ではなく設計上の負債返済なので、6.1 と同時にやる。

### 6.3 条件付き ── 機械の鼓動

**演出の意味**: 待機中、秘書は PC の鼓動を聞いている。

`server` が CPU 使用率を 5秒間隔で `/ws` へ push し、ビーコンの脈の周期に反映する
（例: 負荷 0% で 2.4s、100% で 0.9s）。sysmon が既に btop で同じ値を見ているので、
PC 画面と iPhone が同じものを指していることになる。

**条件**: `DESIGN.md` §3（MVP の非目標）に抵触しないか確認してから入れる。
また常設運用なので push 間隔は 5秒以上にすること（1秒 push は電池を食う）。
**MVP から外してよい。** 6.1 / 6.2 のほうが優先度が高い。

### 6.4 不採用 ── Hyprland のワークスペース／フォーカス連動

どのワークスペースを見ているか、何にフォーカスしているかを秘書側に出す案。
**採らない。** 秘書の役割（音声で用件を受け、Vault に書く）と関係がなく、
画面の情報量が増えて状態の可読性が落ちる。演出として面白いだけでは入れない。

### 6.5 不採用（将来）── 壁紙と秘書画像の同期

壁紙の系統に合わせて秘書画像そのものを差し替える案。
素材が壁紙の数だけ要る。現時点で3世代しかないので成立しない。
素材が増えたら再検討する。

## 7. 実装手順

1. **素材の書き出し**
   - 2枚を同一サイズ（1672×940 推奨）に揃える
   - WebP へ変換する。`magick <in>.png -quality 82 -define webp:method=6 <out>.webp`
   - **PNG のまま置かないこと。** 2枚で 6MB を超え、Wi-Fi 経由の初回表示が固まる
   - PNG 原本は `apps/iphone-ui/.asset-backup/source/` へ
   - 置き場所は `apps/iphone-ui/public/assets/secretary-{sleep,awake}.webp`
   - 参照は `src/components/Secretary.tsx` の2箇所のみ
2. **配色**（3.1）— `src/style.css` のトークンを差し替え、彩度を全廃する
3. **レイアウト**（4）— `object-position` を `38% 44%` に、左フェザーを強める
4. **状態表現**（5）— STANDBY を `brightness(.17) saturate(.2)` に、THINKING を彩度の脈に
5. **6.1 / 6.2** — `scheme.changed` の push と、パネル側の読み替え
6. `DESIGN.md` §15 を更新する（→ 9節）
